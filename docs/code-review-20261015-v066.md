# 0.6.6 代码审查

审查范围：单账号网页控制台、SAZ 导入、游戏连接与心跳、自动种收、任务与好友操作。重点检查游戏协议变化、断线、写操作结果不确定、状态误读和移动端操作。

| 优先级 | 发现 | 处理 |
| --- | --- | --- |
| P1 | 游戏断线后，观察任务只更新页面状态，连接对象、HTTP 会话和账号锁留到下一次授权才释放。 | 观察任务停止调度后主动关闭连接和会话、释放锁；避免取消自己。 |
| P1 | 写请求的游戏回包在业务层解析失败时，可能只暂停调度，却保留可继续操作的连接。 | 自动和手动操作遇到协议解析异常时断开连接，要求重新授权和核对游戏状态。未知结果不自动重发。 |
| P1 | 断线后页面继续依据旧土地记录推算成熟，直接显示“可收获”，容易被理解为实时状态。 | 状态接口提供 `snapshot_fresh`；离线时显示上次同步时间、预计成熟和待联网确认。 |
| P2 | 任务接口明确拒绝会连带停止独立的种收调度。 | 自动任务记录拒绝原因，只跳过该次检查；按既有间隔再检查。写入结果不明仍停止。 |
| P2 | SAZ 压缩包可包含大量解压后的 WebSocket 记录，导入时占用过多内存和处理时间。 | 限制归档成员、请求头、农场会话总量及帧头长度；不解压无关文件。 |
| P2 | 手动刷新使用任意状态更新时间限流，局部库存更新也可能让完整刷新被跳过，页面却提示已刷新。 | 单独记录完整刷新时间；接口返回是否真的刷新，页面据此提示。 |
| P2 | 连接成功后仍需手动开始挂机，但入口在工具栏，容易误以为导入即开始；手机端原本隐藏了唯一的退出入口。 | 概览上方显示下一步与按钮；移动端提供退出入口，调整窄屏布局和小字号。 |
| P3 | 操作已确认但随后状态读取失败时，页面仍显示成功文案，掩盖状态未更新。 | 明确提示“操作已提交、页面未更新”，引导核对。 |

## 仍需遵守的边界

- 临时登录 code 不能假定可重用。进程重启、服务器要求下线或连接失效后，需要新的成功登录 SAZ；不能靠自动重连保证恢复。
- `Kickout` 通知目前只能确认游戏要求下线，不能由此判断是风控、异地登录还是会话策略变化。若要进一步归因，需要只分析通知结构和时间关系，不能猜测并自动绕过。
- 对未知错误码、未知回包字段及已发送但结果不明的购买、出售、播种、领奖，应停手、读取游戏现状或重新授权；不要盲目重试。好友已确认的“目标变化”和当天次数上限仍按现有规则跳过。
- 手动操作的请求标识在服务进程内去重。服务重启后，游戏侧并无可证明的幂等保证；如要继续改进，可把操作回执持久化，但仍必须以游戏当前状态核对结果。

本次校验包含 Python 测试、前端逻辑测试、静态检查和生产构建。真实游戏的新协议分支仍需用户使用新鲜 SAZ 在部署后验证。
