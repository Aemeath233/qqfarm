# 更新记录

## 0.6.8

- 放虫、放草请求成功但回包和只读复查仍未确认全部目标时，仅暂停相应的好友互动类型，其他挂机和心跳继续。保存暂停原因与复查统计，不重复发送同一批操作；用户核对游戏后可手动恢复该类互动。
- 复查时记录目标总数、返回地块数、本账号标记数与任意标记数，便于后续分析游戏实际返回结构；不记录授权内容或完整回包。

此改动对应 0.6.7 线上一次 24 块好友地批量放虫后的安全停手。现有日志无法证明全部地块是否成功，不能把 RPC 成功直接算作 24 次互动。该类互动的准确识别仍需新的游戏回包或状态证据。

## 0.6.7

- 任务领奖请求收到成功回包但未列出领取状态时，额外执行一次只读 `TaskInfo` 查询。确认已领取才计入成功；仍无法确认则停手，不重复领奖，并在概览说明断线原因。
- 好友放虫、放草请求成功但回包未列出目标地块时，只读复查好友地块。仅在所有目标都显示本账号的操作标记后计入成功并继续；否则停止，不重复放置。
- 这两处修复针对实际运行中“游戏请求成功、业务回包没有完整状态”的情况；不根据空回包直接猜测结果。

线上 0.6.5 于 2026-10-16 08:38 曾在放虫回包后暂停调度，16:01 的领奖回包后主动断开连接。服务器进程未重启；当时游戏心跳持续到 16:00:42。既有日志未保存完整业务回包，实际奖励是否到账需登录游戏核对。

## 0.6.6

- 游戏断线后停止调度并释放会话、账号锁；页面区分游戏要求下线与普通连接中断，无法从下线通知判断具体原因时不猜测风控。
- 断线后保留上次农场数据供参考，但明确标出上次同步时间，把推算的成熟地块标为“预计成熟”，避免误认成实时确认。
- 自动或手动操作遇到无法解析的游戏回包时断开连接，防止继续发送可能重复的写操作。任务接口明确拒绝时只跳过该次任务检查，种收调度继续，并在任务页显示原因。
- 对 Fiddler SAZ 的记录数、解压后的会话大小和帧头长度设限，避免异常归档占用过多内存和处理时间。
- 手动刷新基于最近一次完整同步限流；页面区分实际刷新与十秒内复用状态，操作成功但页面读取失败时不再显示“已刷新”。
- 页面突出“导入 SAZ → 开始挂机”的操作顺序，离线时标记旧数据，增加移动端退出入口，并调整小屏好友设置与文字可读性。

本版是源码审查后的改进；服务端仍需单独部署。未知游戏错误保持停止或等待核对的保守行为，不自动猜测协议含义或重复提交。

## 0.6.5

- 新版 `PlayerLogin` 回包不含旧版登录回包的服务器时间字段；用该方法连接时先以本机时钟初始化，收到心跳回复后再校准，避免登录成功后因时间为 0 而断开。
- 将协议解析错误转换为页面可读的 HTTP 409 提示，不再显示泛化 HTTP 500。

修复根据 0.6.4 服务器日志中的真实异常：`PlayerLogin` 成功后，`sync_clock(0)` 抛出协议错误。

## 0.6.4

- 兼容 QQ 农场新版 `UserService.PlayerLogin` 抓包。上传校验与服务端连接均使用 SAZ 中实际登录接口、成功回复和客户端模板；保留旧 `Login` 版本兼容。
- 识别新版登录模板中的系统标记，防止用错 OS 模板。

这次修复依据 2026-10-15 用户 Fiddler 抓包：客户端版本 `1.15.0.1_20261001`，`PlayerLogin` 成功回包错误码为 0 并包含有效玩家 ID；同一会话还有成功的买种请求。

该 SAZ 在本机离线解析成功；分析时登录记录已超过 5 分钟授权窗口，不能再作为新的线上授权使用。部署后需重新抓包。

## 0.6.3

- 修复成熟地块漏调度：一轮种收过程中有其他地块到时，下一次检查优先处理这些地块，不再等新种作物的成熟时间。
- 将已确认的游戏业务提示自动处理：Farming / 1001057（作物不需要务农）和好友 Harvest / 1001040（果实被人摘走）本次跳过，之后继续正常检查；1001046（操作次数已达上限）只停止该类互动当天的操作，次日自动恢复。
- 迁移旧版因这三种已知错误保存的长期暂停。当天上限按原拒绝记录的日期迁移，不因重启额外延长一天；未知错误保持原暂停。
- 页面区分“当天已达上限”和需要人工处理的暂停，显示助手记录与游戏上限判定的区别。
- 好友帮助按当前照料需求判断，不再因同一作物之前已帮助过一次而跳过后续的新需求。

已知错误含义来自当前游戏实际返回的文字说明。静态检查和网页构建用于检查本次改动；未运行自动化测试，新版自动处理流程待实际运行核验。

## 0.6.2

- 好友帮助和采摘被拒绝后，只重新查询一次目标状态。如果发现原目标已不满足操作条件，跳过这次，不重复提交，也不把它计入成功次数。没有发现状态变化时，仍暂停相应互动，等待手动确认。
- 照料回包未完整确认时，重新读取土地。复查确认目标已经无需照料后继续运行，不重复照料，不把未直接确认的结果计入帮助次数；好友照料仍无法核实时只暂停帮助，不中断自家种收。
- 读取游戏回包中的文字错误说明，隐藏已知授权信息后显示和记录；同时记录回包正文长度。旧日志只有错误码，不能补出原来的说明。
- 修正页面提示：未挂机或已断开连接时，明确显示当前状态。
- README 补充持续运行要求、服务器部署建议和 Fiddler Classic / SAZ 授权步骤。
- 将仅供研究的两项心跳工具测试移到本地历史目录，公开测试不再依赖退役模块。

本次进行了 Python 静态检查和网页生产构建。未运行自动化测试，也未通过真实游戏操作验证状态复查流程。错误码 1001040、1001057 的具体含义仍未确认。
