# 0.6.1 代码审查与改进记录

日期：2026-10-13。范围为当前服务器版：网页操作与状态同步、FastAPI、SAZ 授权解析、农场调度、游戏连接、日志和好友统计。历史 Windows 版未作为本次产品修改范围。

## 已修复的问题

| 优先级 | 原问题及影响 | 修复 |
| --- | --- | --- |
| P1 | 出售数量填 0 会被 `value || 全部库存` 当作未填，可能出售全部库存。 | 0、负数、小数和超库存均拒绝；只有空白输入使用全部库存。 |
| P1 | 点击开始时未保存的计划不会生效；保存请求返回后会覆盖保存期间的新修改。 | 开始前保存当前计划；保留请求期间的新修改，仍有新修改时阻止启动。 |
| P1 | 等待中无法在网页暂停；排队的手动动作可能在暂停后重新启用写操作。 | 暂停可独立提交；排队动作检查暂停代次，取消后不发送游戏请求。已发送请求仍核对结果。 |
| P2 | 状态轮询重叠或乱序；本地草稿未与其他页面或服务端更新正确合并。 | 合并同一状态请求，丢弃修改前的旧响应；保留已修改字段并接受其他服务端更新。 |
| P2 | 所有库存专属种子的商品 ID 为 0，Vue 列表标识重复。 | 使用种子 ID 与商品 ID 的组合。 |
| P2 | 植物卡片占空间，移除和排序入口不明确。 | 改为文字表格；优先级直接上移、下移、移除；允许清空优先级，明确白萝卜回退或保留空地的行为。 |
| P2 | 施肥后可能按施肥前的成熟时间等待。 | 下一次检查使用施肥回包更新后的土地状态。 |
| P2 | 一轮中的后续动作失败时，已成功播种的土地仍可能显示为原来的空地。 | 无论本轮是否完整结束，都同步已经确认的土地及库存状态。 |
| P2 | 未确认活动种子的第一次播种可能关联四格；后续仍沿用旧的空地列表。 | 每次播种后重算布局；完整回包确认的单格或四格尺寸按游戏版本缓存。首次未知布局仅在有足够安全空间时尝试，回包不完整则停止。 |
| P2 | 连接创建阶段异常或取消可能留下会话与账号锁；重新登录可能残留旧账号缓存。 | 将资源创建纳入异常清理，重新连接前清空旧缓存及本轮计数。 |
| P2 | 清空旧日志后 SQLite 可能复用编号，好友统计游标会漏记；七天日志保留规则只在启动时执行。 | 使用独立递增编号并兼容已有统计游标；常驻运行时定时清理过期日志。 |
| P2 | 请求只依靠 Content-Length 限制，流式请求可能绕过限制；无效长度导致内部错误。 | 统计实际接收字节，超限返回 413；无效或负长度返回 400。 |
| P2 | SAZ 时间检查未严格匹配登录请求序号与服务，可能误认无关回包时间。 | 只接受对应 UserService.Login 的成功回包；无关服务或不同序号不能提供登录时间。 |
| P3 | 代理返回 HTML 时页面显示 JSON 解析错误；网络等待没有明确超时或进度。 | 显示可读的 HTTP/网络错误和操作阶段；超时不自动重发写操作。 |
| P3 | 零肥料余量会显示“已成熟”，未知参考价格显示 0。 | 时间余量显示 0 秒，未知价格显示未提供。 |

## 按使用反馈调整的界面

- 账号、金币、土地和可用植物统计只放在农场概览。
- 去掉植物装饰图标；种植、好友和日志使用紧凑文字列表。
- 好友页顶部显示今日互动排行，只展示本助手确认成功的好友。合计为帮助、采摘、放虫、放草的地块次数之和；一批请求包含多块地时分别累计。
- 好友暂停原因、今日放虫/放草用量和恢复按钮直接显示在相应操作区。
- 设置在桌面左右分栏显示，小屏改为单栏；输入带明确标签，任务查询间隔以小时展示。
- 成熟后检查延迟的新默认值为 60 秒。已有的自定义值保留。
- 增加统一的未保存提醒、保存和撤销入口；关闭页面时提醒未保存修改。
- 邮件页面、查询、自动领取、手动领取 API 和游戏请求白名单全部移除。旧配置中的 `auto_mail` 在加载时丢弃，其他设置保留。

## 保留的实际限制

手动动作仍需等待游戏查询和回包，随机等待也会增加时长；本版显示进度并区分超时，不能把等待直接当作失败后重发。操作幂等标识目前只在服务进程内保留。

活动种子的布局缓存仅记录完整成功回包确认的单格或四格尺寸，并在游戏版本变化时失效；其他尺寸及不完整回包不会猜测。

服务重启仍会断开农场连接，需要重新上传 SAZ 并手动启动。此次改版没有实现授权自动续期。
